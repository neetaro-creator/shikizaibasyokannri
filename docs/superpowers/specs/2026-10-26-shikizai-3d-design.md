# 積載資器材 3D ビューア 設計書

作成日: 2026-10-26
対象: 信楽分署(甲賀消防)所有車両 4 台

## 1. 目的

「あの資器材はどの車のどこに積んであるか」「全部で何個あるか」を、署内の PC・タブレット・出動先のスマホから数秒で確認できるようにする。
名前を思い出せない資器材でも、分類や車両の場所から探せるようにする。

### 成功基準

- 品名(漢字・ひらがな・通称)で検索すると、車両別・場所別の数量と全車合計が出る。
- 資器材を選ぶと、車両 3D 上で積載場所が光る。
- 3D 上の場所(シャッター等)をタップすると、そこの積載品一覧が出る。
- 一度開いた端末では電波がなくても表示できる。
- スマホ(iPhone 16 程度)で 3D が操作に支障ない速さで動く。

|---|---|---|
| `tank1` | 信楽タンク1(水槽付き消防ポンプ自動車) | 点検表 R8.7.22 |

## 3. データ設計

正本はリポジトリ内の CSV(GitHub の画面で直接編集できる形)。ビルド時に JSON に変換してアプリに同梱する。

### `data/vehicles.csv`
| 列 | 例 |
|---|---|
| `vehicle_id` | `tank1` |
| `name` | 信楽タンク1 |
| `type` | タンク / ポンプ / 指揮 / 救急 |
| `model` | `models/tank1.glb`(未作成時は空 → 仮モデル) |

### `data/locations.csv`
| 列 | 例 |
|---|---|
| `location_id` | `tank1-right-front` |
| `vehicle_id` | `tank1` |
| `name` | 車両右側前部シャッター |
| `group` | 右側 / 左側 / 後部 / 上部 / キャビン / 車内 / 車外保管 |
| `hotspot` | 3D 上の箱 `x,y,z,w,h,d`(空なら 3D 表示なし、一覧のみ) |
| `photo` | `photos/locations/tank1-right-front.jpg`(任意。シャッターを開けた状態) |

段(上段・下段など)は場所名に含め、`location_id` を分ける。

### `data/items.csv`
| 列 | 例 |
|---|---|
| `item_id` | `carabiner` |
| `name` | カラビナ |
| `aliases` | `からびな;karabiner` |
| `category` | 救助 / 消火 / 照明・電源 / ロープ・器具 / 工具 / 救急 / 書類・通信 / その他 |
| `photo` | `photos/items/carabiner.jpg`(任意) |
| `model` | `models/items/carabiner.glb`(任意) |

### `data/stock.csv`
| 列 | 例 |
|---|---|
| `item_id` | `carabiner` |
| `location_id` | `tank1-right-lower-box` |
| `qty` | `5` |
| `qty_note` | 数が「適量」「一式」「一対」等のときの原文 |

`qty` が数値にできない場合は空にし、`qty_note` に原文を入れる。合計はこれを除いた数値で計算し、「ほか適量あり」と表示する。

### 初回変換

- `tools/import_xlsx.py` で 4 ファイルから上記 CSV の下書きを生成する。
- 帳票の列対応が曖昧な行は `data/review.csv` に出し、人が実物と照合して確定する。
- 品名の表記ゆれ(例:「吸管スパナ」の重複、「アルミカラビナ(ピンロック)」と「カラビナ」)は別品目として扱い、通称で横断検索できるようにする。同一品として合算するかは照合時に決める。

## 4. 画面

1. **検索(トップ)**
   - 品名・通称で部分一致検索。ひらがな/カタカナ/全角半角の違いを吸収する。
   - 結果に全車合計と、車両×場所×数量の内訳を表示。
2. **探す(名前が思い出せないとき)**
   - 分類ごとの写真一覧(写真未登録は品名カード)。
   - 車両の 3D から場所をタップして中身を見る。
3. **資器材詳細**
   - 合計、内訳、写真(あれば 3D)。
   - 積載場所を選ぶと、その車両の 3D に移り該当場所が光る。
4. **車両 3D**
   - 回転・拡大縮小。場所の箱をタップすると積載品一覧(シートで下から表示)。
   - 「光らせる」対象がある場合は発光+点滅で示し、カメラをその場所に向ける。
5. **一覧**
   - 車両別の全積載品。
   - 資器材別の総数一覧(並べ替え:品名・合計数)。

管理者向けに「位置合わせモード」を付ける:3D 上で場所の箱を動かし、`hotspot` の値を表示してコピーできる。

## 5. 3D

### 車両
- RealityScan(iPhone 16、Standard Mode)で撮影した GLB を使う。
- 取り込み時に処理:向き・原点・実寸(全長)を合わせる、地面と周囲の不要部分を削除、ポリゴン削減、Draco 圧縮、テクスチャ縮小。目標 1 台 3〜5MB。
- スキャン未着の車両は、箱を組み合わせた仮モデル(キャブ・ボディ・シャッター面)を自動生成して表示する。後でスキャンに差し替える。
- 場所の「光る」表示は、スキャン形状とは別の半透明の箱(hotspot)で行う。スキャンのシャッターは開閉しない。

### 資器材
- 任意。写真が揃った品から追加する。最初は写真表示。
- 撮影は RealityScan の Object Mode。

## 6. 技術構成

- Vite + TypeScript + three.js。UI は素の DOM(フレームワークなし)で小さく保つ。
- PWA(Service Worker でアプリ本体・データ・3D モデルを端末に保存し、オフラインで動く)。
- 公開先: GitHub Pages(GitHub Actions でビルド・配信)。
  - 注意: リポジトリが非公開の場合、GitHub Pages は有料プランが必要。公開リポジトリにする場合、ナンバー等の扱いを公開前に確認する。
- データ更新: CSV を編集してコミット → 自動で再ビルド・配信。

### ディレクトリ

```
data/            正本 CSV
public/models/   車両・資器材の GLB
public/photos/   写真
src/data/        CSV→型付きデータ、検索、集計
src/three/       シーン、車両読み込み、仮モデル生成、hotspot
src/ui/          各画面
tools/           xlsx 取り込み、GLB 圧縮
```

## 7. エラー・欠損時の扱い

- 3D モデルが読めない → 仮モデルで表示し、その旨を小さく出す。
- `hotspot` 未設定の場所 → 3D では光らせず、一覧と場所名で示す。
- CSV の不整合(存在しない `item_id`/`location_id`)→ ビルドを失敗させ、該当行を表示する。

## 8. テスト

- 単体テスト(Vitest): CSV 読み込みと検証、検索の表記ゆれ吸収、合計計算(「適量」混在含む)。
- 取り込みスクリプト: 4 ファイルから期待件数・代表品目(例:タンク1 右側下部BOX のカラビナ 5)が出ること。
- 画面確認(Playwright): スマホ幅で検索 → 詳細 → 3D で光る、までを通し、スクリーンショットを残す。
