# 積載資器材 3D ビューア Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 信楽分署の車両 4 台の積載資器材を、検索・総数・車両別数量・3D 上の積載場所で示す PWA を作る。

**Architecture:** 正本は `data/*.csv`。Vite のビルド前処理で CSV を検証して `src/generated/db.json` に変換し、アプリに同梱する。UI は素の DOM + TypeScript、3D は three.js。スキャン GLB がない車両は仮モデルを自動生成する。Service Worker でオフライン化し、GitHub Pages に Actions で配信する。

**Tech Stack:** Node 20, Vite 5, TypeScript 5, three.js 0.16x, vite-plugin-pwa, Vitest, Playwright(プリインストール済み Chromium), Python 3 + openpyxl(取り込みのみ), @gltf-transform/cli(GLB 圧縮のみ)

**Spec:** `docs/superpowers/specs/2026-10-26-shikizai-3d-design.md`

## Global Constraints

- 車両 ID は `tank1` / `pump1` / `command1` / `ambulance1` の 4 つ。
- CSV の列名・意味は設計書 §3 のとおり(`vehicles.csv` / `locations.csv` / `items.csv` / `stock.csv`)。
- `qty` が数値でない行(適量・一式・一対・各1 等)は `qty` 空、原文を `qty_note` に入れる。合計は数値分のみで、`qty_note` のある内訳が 1 件でもあれば「ほか適量あり」を表示する。
- 画面の文言は日本語。スマホ幅(390px)で横スクロールなし。
- 3D モデル 1 台 3〜5MB 目標。モデル読み込み失敗時は仮モデルにフォールバック。
- CSV の参照不整合はビルド失敗にし、ファイル名・行番号を出す。
- `base` は GitHub Pages のサブパス `/shikizaibasyokannri/`。

## Review Focus

1. 「ほか適量あり」:合計が 0 でも数値なし内訳だけある品(例:吸着マット)で「0 個」と出ず「適量」と出ること → Task 3 のテスト。
2. 検索の表記ゆれ:全角/半角英数・カタカナ/ひらがな・空白・「㎜」と「mm」の違いで同じ結果になること → Task 3 のテスト。
3. 同名品が同じ車両の複数場所にある(タンク1「吸管スパナ」が左右両側)→ 内訳が場所ごとに出て合計が足し算されること → Task 3 のテスト。
4. `hotspot` 未設定の場所を持つ資器材で 3D へ移ったとき、例外にならず場所名だけ示されること → Task 6 のテスト。
5. オフライン:一度開いた後に通信を切って再読込しても検索と 3D が動くこと → Task 8 の E2E。

### Task 1: 点検表取り込みスクリプトと照合リスト

**Files:**
- Create: `tools/import_xlsx.py`, `tools/import_config.json`, `tools/test_import_xlsx.py`
- Create(生成物をコミット): `data/vehicles.csv`, `data/locations.csv`, `data/items.csv`, `data/stock.csv`, `data/review.csv`
- Create: `tools/fixtures/`(元 xlsx 4 点をコピー。ファイル名は `tank1.xlsx` 等の車両 ID に改名)

**Interfaces:**
- Produces: 上記 CSV(UTF-8、BOM なし、ヘッダ行あり)。`review.csv` の列は `vehicle_id,sheet,cell,raw,reason`。
- CLI: `python3 tools/import_xlsx.py tools/fixtures data`

**方針:** 帳票は列帯(品名列+数量列の組)が横に 2〜3 本並ぶ。`import_config.json` に車両ごとに `sheets` と列帯 `[{"name_col":"C","qty_col":"H"}, ...]`、場所見出しの正規表現(`シャッター|BOX|ＢＯＸ|上段|中段|下段|最上段|キャビン|運転席|助手席|車両上部|収納|患者室|車庫|書庫|ロッカー`)を書く。各帯を上から読み、見出しにマッチしかつ数量欄が空のセルで「現在の場所」を更新、それ以外の品名+数量を 1 行の在庫にする。段(上段等)単独の見出しは直前の大見出しに連結する(例:「車両左側後部シャッター 上段」)。点検項目(「作動状況」「油量」「清掃」「充電」等の数量欄)は在庫から除外し `review.csv` に reason=`inspection` で出す。帯の判定ができないセル・場所が未確定のまま現れた品名は reason=`unplaced` で出す。`item_id` は品名を正規化したもののスラッグ(ローマ字化はしない。`i0001` 形式の連番+名前で辞書管理し、同一正規化名は同じ ID)。

  - `test_tank1_carabiner`: tank1 に場所名「車両右側下部ＢＯＸ」(正規化後一致)・品名「カラビナ」・qty `5` の行がある。

  ```ts
  type VehicleId = 'tank1'|'pump1'|'command1'|'ambulance1';
  interface Vehicle { id: VehicleId; name: string; type: string; model?: string }
  interface Hotspot { x:number; y:number; z:number; w:number; h:number; d:number }
  interface Location { id: string; vehicleId: VehicleId; name: string; group: string; hotspot?: Hotspot; photo?: string }
  ```

### Task 3: 検索と集計

**Files:**
- Create: `src/data/normalize.ts`, `src/data/query.ts`
- Test: `src/data/query.test.ts`

**Interfaces:**
- Consumes: `Db`。
- Produces:
  ```ts
  normalize(s: string): string                         // NFKC、カタカナ→ひらがな、空白除去、小文字、「㎜」→「mm」
  search(db: Db, q: string): Item[]                    // name+aliases の部分一致、前方一致を先頭に
  interface Breakdown { vehicle: Vehicle; location: Location; qty?: number; qtyNote?: string }
  interface ItemSummary { item: Item; total: number; hasUncounted: boolean; breakdown: Breakdown[] }
  summarize(db: Db, itemId: string): ItemSummary
  itemsAt(db: Db, locationId: string): { item: Item; qty?: number; qtyNote?: string }[]
  itemsByVehicle(db: Db, vehicleId: VehicleId): { location: Location; items: ReturnType<typeof itemsAt> }[]
  totals(db: Db): ItemSummary[]
  formatTotal(s: ItemSummary): string                  // "12" / "12(ほか適量あり)" / "適量"
  ```
- [ ] **Step 1: テスト**(小さな手書き Db フィクスチャで):
  - `search("ｶﾗﾋﾞﾅ")` と `search("からびな")` が「カラビナ」を返す。
  - `search("65mm")` が「65㎜ホースバッグ」を返す。
  - 同一車両 2 場所に qty 1 ずつ → total 2、breakdown 2 件。
  - qty なし・qtyNote「適量」のみ → `formatTotal` が `適量`。
  - 数値 3 + 適量 1 件 → `3(ほか適量あり)`。
- [ ] **Step 2:** FAIL 確認。 **Step 3:** 実装。 **Step 4:** PASS。
- [ ] **Step 5:** コミット `feat: 資器材検索と合計集計`

### Task 6: 車両 3D(仮モデル+hotspot)

**Files:**
- Create: `src/three/scene.ts`, `src/three/placeholder.ts`, `src/three/hotspots.ts`, `src/three/load-vehicle.ts`, `src/ui/vehicle-view.ts`(Task 4 の一覧版を置き換え、一覧は下部シートとして残す)
- Test: `src/three/hotspots.test.ts`, `e2e/vehicle3d.spec.ts`

**Interfaces:**
- Produces:
  ```ts
  createScene(canvas: HTMLCanvasElement): { scene; camera; controls; dispose(): void }
  buildPlaceholder(type: Vehicle['type']): THREE.Group          // 全長: タンク 7.0m, ポンプ 6.2m, 指揮 4.7m, 救急 5.6m。前方 +X、上 +Y、地面 y=0
  loadVehicle(v: Vehicle): Promise<THREE.Object3D>              // model があれば GLTFLoader+DRACOLoader、失敗/なしは buildPlaceholder
  createHotspots(locations: Location[]): { group: THREE.Group; pick(ndc: THREE.Vector2, camera): string | undefined; highlight(id?: string): void }
  ```
  hotspot は半透明(opacity 0.15)の箱、`highlight` で発光色 #ffd400・opacity 0.6・1 秒周期の点滅、カメラを箱の正面へ移動。
- 仮モデル用の hotspot 初期値:Task 1 の場所 `group`(左側/右側/後部/上部/キャビン/車内)と同 group 内の順番から、ボディ側面を等分した位置を自動計算する関数 `defaultHotspot(loc, indexInGroup, countInGroup, type): Hotspot` を `placeholder.ts` に置く。CSV に `hotspot` があればそちらを優先。

- [ ] **Step 1: テスト**:`defaultHotspot` が右側 3 区画で重ならず全長内に収まる。`createHotspots` の `pick` が箱中心を指す NDC で該当 ID を返す(カメラ固定)。hotspot 未設定かつ group が「車外保管」の場所は 3D 対象外で、`highlight` に渡しても例外にならない。E2E:詳細の内訳から 3D に移ると該当場所の箱が点滅状態(`data-highlight` 属性を canvas 親に出す)、箱タップで下部シートに積載品一覧。
- [ ] **Step 2〜4:** FAIL → 実装 → PASS、スクリーンショット送付。
